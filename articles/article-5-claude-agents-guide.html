4 · Your First Agent — Messages API

Before the Managed Agents SDK, master this: the Messages API + tool use loop. It is the foundation every agent is built on.

4.1 · Single-Turn Agent

The simplest possible agent: one message in, one response out.

pythonsingle-turn.py
from anthropic import Anthropic

client = Anthropic()

response = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=1024,
    messages=[{"role": "user", "content": "What is 2+2?"}]
)

print(response.content[0].text)

4.2 · Multi-Turn Conversation Agent

Maintain a conversation_history list and append each turn. Claude sees the full history on every call.

pythonmulti-turn.py
client = Anthropic()
history = []

def chat(user_message: str) -> str:
    history.append({"role": "user", "content": user_message})
    response = client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=2048,
        system="You are a helpful assistant.",
        messages=history
    )
    reply = response.content[0].text
    history.append({"role": "assistant", "content": reply})
    return reply

print(chat("I'm learning agents."))
print(chat("What should I learn first?"))

4.3 · Tool Use / Agentic Loop

This is the core agentic pattern. Define tools (functions), and Claude decides when to call them. The loop continues until stop_reason == "end_turn".

pythontool-use-loop.py
tools = [{
    "name": "get_weather",
    "description": "Get current weather for a city",
    "input_schema": {
        "type": "object",
        "properties": {"city": {"type": "string"}},
        "required": ["city"]
    }
}]

def execute_tool(name, inputs):
    if name == "get_weather":
        return f"Weather in {inputs['city']}: 22°C, partly cloudy"

def run_agent(user_message):
    messages = [{"role": "user", "content": user_message}]
    while True:
        resp = client.messages.create(
            model="claude-sonnet-4-6", max_tokens=4096,
            tools=tools, messages=messages
        )
        if resp.stop_reason == "end_turn":
            return resp.content[0].text

        messages.append({"role": "assistant", "content": resp.content})
        results = []
        for block in resp.content:
            if block.type == "tool_use":
                result = execute_tool(block.name, block.input)
                results.append({
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": result
                })
        messages.append({"role": "user", "content": results})

4.4 · Streaming Responses

pythonstreaming.py
with client.messages.stream(
    model="claude-sonnet-4-6", max_tokens=1024,
    messages=[{"role": "user", "content": "Write a haiku about coding"}]
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)

5 · Claude Managed Agents SDK

Core Concepts

  • Agent — Reusable config: model + system prompt + tools + MCP servers
  • Environment — Cloud sandbox or self-hosted container where code runs
  • Session — One running instance of an agent working on a task
  • Events — SSE stream of messages between your app and the agent
  • Outcome — Optional success criteria; agent iterates until satisfied
pythonmanaged-agent-quickstart.py
from anthropic import Anthropic
client = Anthropic()

# 1 — Create a reusable agent definition
agent = client.beta.agents.create(
    name="My First Agent",
    model="claude-opus-4-7",
    system="You are a helpful coding assistant.",
    tools=[{"type": "agent_toolset_20260401"}],
)

# 2 — Create an execution environment
environment = client.beta.environments.create(
    name="dev-environment",
    config={"type": "cloud", "networking": {"type": "unrestricted"}},
)

# 3 — Start a session
session = client.beta.sessions.create(
    agent=agent.id,
    environment_id=environment.id,
    title="Fibonacci Task",
)

# 4 — Open stream FIRST, then send message
with client.beta.sessions.events.stream(session.id) as stream:
    client.beta.sessions.events.send(session.id, events=[{
        "type": "user.message",
        "content": [{"type": "text", "text": "Write and run fib.py"}],
    }])

    for event in stream:
        if event.type == "agent.message":
            for block in event.content:
                if hasattr(block, "text"): print(block.text, end="")
        elif event.type == "session.status_idle":
            break

Event Types Reference

All agent activity arrives as a stream of typed events.

Event TypeWhen it firesKey fields
agent.messageAgent sends a text response.content[].text
agent.tool_useAgent calls a built-in tool.name, .input
agent.tool_resultTool execution returns.content, .is_error
agent.custom_tool_useAgent calls YOUR custom tool.name, .input, .id
session.status_idleAgent finished its turn—
span.outcome_evaluation_endOutcome rubric evaluated.result ("satisfied"/"unsatisfied")

5.4 · Outcomes — Quality-Driven Iteration

Define a rubric and max_iterations. The agent will keep retrying until the rubric is satisfied.

pythonoutcomes.py
client.beta.sessions.events.send(session.id, events=[{
    "type": "user.define_outcome",
    "description": "Implement a REST API server in Python",
    "rubric": """
- [ ] server.py exists and is runnable
- [ ] GET /health returns 200
- [ ] GET /users returns JSON list
- [ ] POST /users creates a user
- [ ] All endpoints have error handling
""",
    "max_iterations": 5,
}])

for event in stream:
    if event.type == "span.outcome_evaluation_end":
        print(f"Outcome: {event.result}")  # "satisfied" or "unsatisfied"
        if event.result == "satisfied": break

6 · Custom Tools

Give your agent access to your APIs and databases

Custom tools let the agent call your business logic. The agent decides when to call them based on the description — write it clearly.

pythoncustom-tools.py
agent = client.beta.agents.create(
    name="Business Agent", model="claude-opus-4-7",
    tools=[
        {"type": "agent_toolset_20260401"},  # built-in tools
        {
            "type": "custom",
            "name": "get_customer",
            "description": "Fetch customer from CRM by ID. Use when you need customer details or order history.",
            "input_schema": {
                "type": "object",
                "properties": {
                    "customer_id": {"type": "string", "description": "Format: CUS-XXXXX"},
                    "include_orders": {"type": "boolean", "default": False}
                },
                "required": ["customer_id"]
            }
        }
    ],
)

# Handle custom tool calls in the event loop
for event in stream:
    if event.type == "agent.custom_tool_use":
        result = my_crm_api(event.name, event.input)  # your logic
        client.beta.sessions.events.send(session.id, events=[{
            "type": "user.custom_tool_result",
            "tool_use_id": event.id,
            "content": [{"type": "text", "text": result}],
        }])

7 · Multi-Agent Orchestration

Three Orchestration Patterns

  • Coordinator + Specialists — A parent agent delegates to named sub-agents. Best for complex tasks that need different expertise.
  • Pipeline (Sequential) — Each agent's output becomes the next agent's input. Best for data transformation chains.
  • Parallel Fan-Out — Multiple agents run simultaneously via asyncio.gather(). Best for batch analysis (e.g., reviewing 20 files at once).
pythoncoordinator-pattern.py
# Create specialist agents
researcher = client.beta.agents.create(name="Researcher", model="claude-opus-4-7", ...)
writer     = client.beta.agents.create(name="Writer",     model="claude-sonnet-4-6", ...)

# Create coordinator that delegates to them
coordinator = client.beta.agents.create(
    name="Project Coordinator",
    model="claude-opus-4-7",
    system="You coordinate: researcher + writer. Delegate appropriately.",
    multiagent={"agents": [{"id": researcher.id}, {"id": writer.id}]},
)
pythonparallel-fan-out.py
import asyncio

async def analyze_parallel(files):
    async def one(f):
        result = await run_agent_task(ANALYZER_ID, f"Analyze {f} for security issues")
        return (f, result)

    return dict(await asyncio.gather(*[one(f) for f in files]))

8 · MCP Servers

Model Context Protocol — plug-in tools for agents

Instead of writing custom tools for every integration, MCP servers are pre-built, standardised connectors. Install once, use in any agent.

  • GitHub — read/write repos, PRs, issues
  • PostgreSQL / SQLite — run queries
  • Slack — read channels, send messages
  • Filesystem — access local files from a sandboxed path
  • Google Drive, Notion, Linear, Jira — and hundreds more
json.claude/settings.json — MCP servers for Claude Code CLI
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}" }
    },
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": { "POSTGRES_CONNECTION_STRING": "${DATABASE_URL}" }
    },
    "slack": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-slack"],
      "env": { "SLACK_BOT_TOKEN": "${SLACK_BOT_TOKEN}" }
    }
  }
}
pythonmcp-in-managed-agent.py — remote MCP via URL
agent = client.beta.agents.create(
    name="DevOps Agent",
    model="claude-opus-4-7",
    mcp_servers=[
        {"type": "url", "url": "https://your-github-mcp.example.com/mcp", "name": "github"},
    ],
    tools=[
        {"type": "agent_toolset_20260401"},
        {"type": "mcp_toolset", "mcp_server_name": "github"},
    ],
)

9 · Claude Code Subagents (CLI)

How Subagents Work

Inside a Claude Code CLI session, you can spawn isolated child agents. Each subagent gets its own fresh context window — no bleed from the parent conversation. Key options:

  • subagent_type — which agent definition to use (Explore, Plan, general-purpose, custom)
  • run_in_background: true — don't block the parent agent
  • isolation: "worktree" — give the subagent its own git branch + worktree so file changes are isolated
markdown.claude/agents/security-reviewer.md — custom subagent definition
---
name: security-reviewer
description: Reviews code for security vulnerabilities. Use when auditing
             authentication, SQL queries, or input validation code.
model: claude-opus-4-7
tools:
  - Read
  - Bash
  - Glob
  - Grep
---

You are a security code reviewer specializing in OWASP Top 10.

For every file you review:
1. Check for injection flaws (SQL, command, LDAP)
2. Check for broken authentication
3. Check for sensitive data exposure
4. Check for XSS vulnerabilities

Report findings as: CRITICAL / HIGH / MEDIUM / LOW with file:line references.
Write self-contained prompts. The subagent has zero context from your conversation. Include file paths, what you've tried, and what "done" looks like. "Fix the bug we were discussing" will fail. "Fix the null pointer in src/api/users.py:47 where get_user_by_id should return None for missing users" will succeed.

10 · Hooks System

Lifecycle callbacks for Claude Code

Hooks run shell commands automatically when events occur in Claude Code. Think of them as middleware between you and every tool call.

EventWhenCan Block?
UserPromptSubmitBefore Claude processes your messageYes
PreToolUseBefore any tool call executesYes — denies the tool
PostToolUseAfter tool call succeedsNo
StopWhen Claude finishes its turnNo
NotificationApp-level notificationsNo
json.claude/settings.json — hook configuration
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{"type": "command", "command": "/path/to/security-check.sh"}]
    }],
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{"type": "command", "command": "npm run lint -- --fix"}]
    }],
    "Stop": [{
      "matcher": "*",
      "hooks": [{"type": "command", "command": "osascript -e 'display notification \"Done\" with title \"Claude Code\"'"}]
    }]
  }
}
bashsecurity-check.sh — block destructive bash commands
#!/bin/bash
COMMAND=$(cat | python3 -c "import sys,json; print(json.load(sys.stdin).get('tool_input',{}).get('command',''))")

for pattern in "rm -rf /" "dd if=" "mkfs" "> /dev/sda"; do
    if echo "$COMMAND" | grep -qF "$pattern"; then
        echo '{"continue": false, "reason": "Destructive command blocked"}'
        exit 2
    fi
done
exit 0

12 · Custom Slash Commands

Reusable commands in .claude/commands/

Create a .md file — the filename becomes the slash command. Use $ARGUMENTS to capture what the user types after the command name.

markdown.claude/commands/review.md → /review src/payments.py
Review the code in $ARGUMENTS for:

1. **Security** — OWASP Top 10, injection flaws, auth issues
2. **Performance** — N+1 queries, unnecessary loops, blocking I/O
3. **Readability** — naming, complexity, missing docs
4. **Tests** — coverage gaps, missing edge cases

Format:
## Summary
## Issues Found  | Severity | File:Line | Issue | Fix |

13 · Real-World Use Cases

13.1 · Automated PR Review Pipeline

Fetch open PRs with gh pr list, create one session per PR, post the review back as a GitHub comment. Run on a cron job for continuous review.

pythonpr-review-pipeline.py
def review_pr(pr_number, title):
    session = client.beta.sessions.create(agent=REVIEWER_AGENT_ID, environment_id=ENV_ID)
    diff = subprocess.run(["gh","pr","diff",str(pr_number)], capture_output=True, text=True).stdout[:50000]

    output = []
    with client.beta.sessions.events.stream(session.id) as stream:
        client.beta.sessions.events.send(session.id, events=[{
            "type": "user.message",
            "content": [{"type": "text", "text": f"Review PR #{pr_number}: {title}\n\n{diff}"}],
        }])
        for event in stream:
            if event.type == "agent.message":
                for block in event.content:
                    if hasattr(block, "text"): output.append(block.text)
            elif event.type == "session.status_idle": break
    return "".join(output)

13.2 · Document Processing Pipeline

An agent reads PDFs/documents, extracts structured data matching your JSON schema, and writes the result. Use outcomes to guarantee quality.

13.3 · Deep Research Agent

The built-in web_search and web_fetch tools give your agent internet access. Combine with a detailed system prompt to get verified, cited research reports.

13.4 · Automated Testing Agent

Define an outcome rubric: "all public functions have tests, coverage > 80%, pytest exits 0". The agent writes tests, runs them, fixes failures — and iterates until the rubric is satisfied.

14 · Common Gotchas

G1Open the stream BEFORE sending a message

If you send the message first, events fired during startup are lost. Always open the stream context manager, then call events.send() inside it.

with client.beta.sessions.events.stream(session.id) as stream: → then send.

G2Subagent prompts must be 100% self-contained

The subagent has zero context from your conversation. Include file paths, what you've already tried, what success looks like, and any constraints. "Fix the bug" fails. "Fix the null pointer in src/api/users.py:47" succeeds.

G3Store Agent IDs — don't recreate on every run

Agent and Environment objects are persistent in Anthropic's system. Recreating them every run wastes API calls and creates orphaned resources. Save the IDs to a config file on first creation and load them on subsequent runs.

G4Not all content blocks have text

When iterating event.content on agent.message events, always check if hasattr(block, "text") before printing. Tool use blocks don't have a text attribute and will raise AttributeError.

G5Model selection has a big impact on cost and speed

claude-opus-4-7 → complex reasoning, orchestration (slow, high cost). claude-sonnet-4-6 → balanced default (medium). claude-haiku-4-5-20251001 → high-volume, simple tasks (fast, cheap). Don't default everything to Opus.

G6API key not found at runtime

Add this guard at the top of every script: if not os.getenv("ANTHROPIC_API_KEY"): raise EnvironmentError("..."). Fail fast with a clear message rather than a cryptic SDK exception deep in the call stack.
